Experimental local Wi-Fi test build for **AquaSky 3.0 (product 532)** from
[draft PR #146](https://github.com/MrMooreUK/fluvalble/pull/146).
This is a fork build for hardware testing, not a supported release.

This build keeps existing Bluetooth setup unchanged when MQTT isn't
configured. It also limits the time Wi-Fi provisioning can hold the Bluetooth
connection and gives recovery guidance if setup fails partway through.

### Setup

1. Use a test Home Assistant instance or back up your existing Fluval
   integration before installing. This build replaces the normal integration;
   it does not run alongside it.
2. Configure MQTT in Home Assistant with a local broker the fixture can reach.
   Use a trusted network and [dedicated credentials and topic permissions](https://github.com/Wheemer/fluvalble/blob/release/aquasky3-wifi-0.0.17-6/docs/native-local-mqtt.md).
3. Select Bluetooth control in FluvalConnect and close the app. In Home
   Assistant, open the fixture's Bluetooth entry and choose **Configure →
   Fixture connection → Set up Local Wi-Fi over Bluetooth**. This uses Home
   Assistant's Bluetooth route, including an ESPHome Bluetooth proxy.
4. Enter the 2.4 GHz Wi-Fi and broker details. Home Assistant switches the entry
   only after the fixture answers through the broker. If setup fails, the
   fixture may already be on the new network; rerun setup or restore the
   original settings in FluvalConnect.

### What to test

- Provisioning through an ESPHome Bluetooth proxy, then power, colour and state
  readback over local Wi-Fi.
- Broker reconnect and fixture reboot, including a power cut with Internet
  access blocked. Check whether scheduled times remain correct.
- Switching the Home Assistant entry back to Bluetooth and restoring the
  original Wi-Fi setup through FluvalConnect.

Please don't share passwords or raw provisioning traffic.
