Experimental AquaSky 3.0 local Wi-Fi test build from [draft PR #146](https://github.com/MrMooreUK/fluvalble/pull/146), source commit `cf0eabf`. This is a fork-only build for volunteer hardware testing.

Use a test Home Assistant instance or back up your existing Fluval integration before replacing it with the test ZIP. This package uses the same integration domain; it is not installed alongside the regular version.

### Setup

1. Configure Home Assistant's MQTT integration with an owner-controlled local broker reachable by the light.
2. In FluvalConnect, select Bluetooth control mode and close the app. Do not delete the fixture.
3. Add or open the light's Bluetooth entry in Home Assistant. Choose **Configure → Fixture connection → Set up Local Wi-Fi over Bluetooth**. Home Assistant uses its active Bluetooth route, including an ESPHome proxy.
4. Enter the 2.4 GHz Wi-Fi details and local broker details. Home Assistant switches the existing entry only after the fixture responds over MQTT.

### What to test

- Provisioning through an active ESPHome Bluetooth proxy, then power, colour and state readback.
- Broker reconnect and fixture reboot, including with Internet access unavailable.
- Returning to Bluetooth and restoring official app Wi-Fi by rerunning Wi-Fi setup in FluvalConnect.

Provisioning replaces the saved broker even if the final verification fails. Use a trusted network, dedicated MQTT credentials and restricted topics. Share observations or redacted logs only—not passwords or raw provisioning traffic.
